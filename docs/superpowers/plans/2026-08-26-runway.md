# Product-fidelity runway — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development to
> implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build the foundation runway of master prompt §24.2 — the §12.6 JSON database and
repository, the production product-primitive layer, the demo chrome, the §10.6 tour engine, the
§10.5 Workflow Index, the fourteen §9.6 registry indexes, and the §2.3 live-verification harness
— so that every workflow unit after it can be shipped as real product user interface.

**Architecture:** Approach A from the design: the existing domain, policy, kernel, scenario,
persistence, offline, AI and scheduling layers and all fourteen generated registries are kept
untouched. A new `src/data` layer owns business truth as JSON collections behind one typed
repository. `src/ui` splits into `src/ui/product` (the real product, never importing demo code)
and `src/ui/demo` (chrome). The tour engine drives real product handlers; there is no second
implementation of any flow.

**Tech Stack:** Next.js 16.3.1 App Router (`output: "export"`), React 19.2.8, TypeScript strict,
zod 4.4.3, Tailwind-style CSS custom properties in `app/globals.css`, pnpm 11.20.0. Verification
is real Google Chrome through the Chrome MCP server (`mcp__plugin_superpowers-chrome_chrome__use_browser`).

**Spec:** `docs/superpowers/specs/2026-08-26-product-fidelity-rebuild-design.md`

## Global Constraints

- **No test cases.** Master prompt §2.3 and APP-017. Do not create, extend or repair any
  `*.test.ts`/`*.test.tsx` file, any Playwright spec, or any snapshot. `/superpowers:test-driven-development`
  is policy-excluded. Existing suites under `tests/` keep running untouched unless a task
  explicitly deletes one alongside the screen it describes.
- **Verification is live.** Every task's green step is a recorded run in real Chrome through the
  Chrome MCP server plus the compile-level checks. Compile-level checks are exactly:
  `pnpm typecheck`, `pnpm lint`, `node scripts/validate-collections.mjs`, `pnpm build`.
- **No backend, ever.** No API route, Route Handler, Server Action, middleware, `fetch` to any
  external origin, secret, or environment variable. `output: "export"` must keep building.
- **No component imports a seed file.** Business truth reaches a component only through
  `src/data/repository.ts`. Enforced by lint from Task 8 onward.
- **`src/ui/product/**` must never import `src/ui/demo/**`.** Enforced by lint from Task 8.
- **§8.6.2 product fidelity.** No file created by this plan may render a blueprint line locator
  (`L42806`), a bare requirement identifier, a narrative paragraph, or a bullet list as the
  primary content of a product screen. Story text belongs in tour narration and the registry.
- **Frozen source** sha256 `47bd18db467817f3edbe3329c8ae5e332013871aaa2df08c2be6fc5afa8d0b27`.
  Re-hash at task entry. If it differs, stop and report source drift — that stop is not waived.
- **Simulated clock only.** No `Date.now()`, `new Date()` with no argument, or `Math.random()`
  in `src/data`, `src/ui/product` or `src/tours`.
- **Accessibility floor:** WCAG 2.2 AA. Every interactive primitive ships with a visible focus
  ring, an accessible name, keyboard operation, and a live-region announcement where it changes
  status.
- **Implementers never run git.** The controller commits.

`scripts/validate-collections.mjs` — plain Node, no TypeScript, so it runs before `tsc`:

```js
#!/usr/bin/env node
import { readFileSync, existsSync } from 'node:fs'
import { join, dirname } from 'node:path'
import { fileURLToPath } from 'node:url'
import { register } from 'node:module'

const root = join(dirname(fileURLToPath(import.meta.url)), '..')
register('tsx/esm', import.meta.url)
const { COLLECTIONS, RELATIONS } = await import(join(root, 'src/data/schemas/index.ts'))

let failed = 0
const fail = (msg) => { console.error(`FAIL  ${msg}`); failed++ }
const loaded = {}

for (const [name, def] of Object.entries(COLLECTIONS)) {
  const path = join(root, 'src/data/collections', def.file)
  if (!existsSync(path)) { fail(`${name}: missing ${def.file}`); continue }
  let rows
  try { rows = JSON.parse(readFileSync(path, 'utf8')) }
  catch (e) { fail(`${name}: not valid JSON — ${e.message}`); continue }
  if (!Array.isArray(rows)) { fail(`${name}: top level must be an array`); continue }

  const seen = new Set()
  rows.forEach((row, i) => {
    const r = def.schema.safeParse(row)
    if (!r.success) {
      for (const issue of r.error.issues) {
        fail(`${name}[${i}] ${issue.path.join('.') || '(root)'}: ${issue.message}`)
      }
      return
    }
    if (seen.has(row.id)) fail(`${name}[${i}]: duplicate id ${row.id}`)
    seen.add(row.id)
  })
  loaded[name] = rows
  console.log(`ok    ${name.padEnd(24)} ${String(rows.length).padStart(5)} rows`)
}

for (const rel of RELATIONS) {
  const src = loaded[rel.from], dst = loaded[rel.to]
  if (!src || !dst) continue
  const ids = new Set(dst.map((r) => r.id))
  src.forEach((row, i) => {
    const v = row[rel.field]
    if (v === undefined) return
    const values = rel.array ? v : [v]
    for (const one of values) {
      if (one === null) { if (!rel.nullable) fail(`${rel.from}[${i}].${rel.field}: null not allowed`); continue }
      if (!ids.has(one)) fail(`${rel.from}[${i}].${rel.field}: "${one}" is not an id in ${rel.to}`)
    }
  })
}

if (failed) { console.error(`\n${failed} problem(s)`); process.exit(1) }
console.log('\nall collections valid')
```

## Seed authoring method — binding on Tasks 4, 5 and 6 (controller ruling R10)

Tasks 2 and 3 are hand-authored: their volume is tens of rows and the recurring cast's names,
scopes and relationships carry meaning that a generator would flatten.

Tasks 4, 5 and 6 are not. Task 5 alone needs 120 runs and, under
`RUN-BB-2026-0418-03`, eight units × six steps with a capture on every step that defines one —
thousands of interdependent rows. Hand-authoring that produces transcription defects nobody can
review, and reviewing it is worse than writing it.

**So Tasks 4-6 ship a deterministic generator plus its output, and both are committed.**

- `scripts/generate-seed.mjs` takes a fixed integer seed and a named scenario and writes the
  collection JSON. It uses a small seeded pseudo-random number generator written inline — never
  `Math.random()`, never `Date.now()` — so the same seed produces byte-identical output.
- The **hand-authored exemplars stay hand-authored.** The recurring cast's own rows —
  `WFD-BB-FRAME-ASSY` and its nine-section screens, `JOB-BB-2026-0418`,
  `RUN-BB-2026-0418-03` and its executions, `DEV-BB-SEV1-01` and its hold — are written by
  hand into a fixtures module the generator reads and emits verbatim. The generator fills the
  population around them; it never invents the story the tours will narrate.
- The generated JSON **is** the database, committed and loaded as plain JSON per §12.6. The
  generator is build-time-only and is not imported by the application.
- Determinism is proved, not asserted: each of Tasks 4-6 runs the generator twice and pastes
  the two output sha256 sets, which must be identical, and confirms `git status` is clean on
  the second run.
- Every generated row still validates. `node scripts/validate-collections.mjs` exit 0 is the
  gate, unchanged.

## Named debts carried out of the runway

These are real gaps found during runway execution that are **not** runway work. Each names the
workflow unit that inherits it, so it cannot be lost between the runway and §24.2's arc.

**D1 — `User.status` is five states short of the source's account lifecycle.**
`AC-15-01` states verbatim that "Account states are the nine named states": Requested, Invited,
IdentityVerified, Activated, Active, Suspended, Reactivated, Revoked, Offboarded. The shipped enum
is `invited, active, suspended, removed`. Missing outright: Requested, IdentityVerified, Activated,
Reactivated, Revoked. And `removed` maps to `Offboarded` only imprecisely — the source gives
Offboarded two distinct upstream paths, an ordinary two-step departure and
`Suspended → Revoked → Offboarded` for cause, which one literal cannot distinguish. This is a
§12.2 vocabulary collapse. **Owner: the §24.2 workflow unit for tenant configuration, users,
Workers, qualifications and devices.** It must widen the enum, seed every state, split the two
Offboarded paths, and carry the transition table `TRN-ACC-01`.. from §15.1 rather than inventing
transitions.

**D2 — Task 1's relation-coverage gate is defeatable by naming.**
It tests field names against `/Ids?$/`, so a genuine foreign key not suffixed `Id` or `Ids` escapes
it silently. Nothing today does — `gateReference` is correctly prose — but the gate's reach is a
naming convention rather than a type. **Owner: the final whole-branch review**, which should decide
whether to widen it or accept the limit explicitly.

**D3 — `tours.steps[].controlId` is allowlisted pending control identity.**
No collection or registry holds stable control identity yet: product primitives only begin emitting
`data-control-id` at Task 9, and `registries/generated/actionable-controls.json` carries descriptive
labels, not ids. **Owner: Task 15**, which must convert the allowlist entry into a real `RELATIONS`
row once the tour engine establishes control identity.

**D4 — a loud-failure guard for unrecognised zod wrappers.**
`unwrap()` keys off `_def.innerType`, a zod 4.4.3 internal. If a future zod reshapes it, the walker
silently drops that subtree — the same silent-under-coverage class the walker exists to prevent.
**Owner: whoever next upgrades zod.**
