# Re-plan — slices 5 through 13

**Written** 2026-08-21. **Supersedes** the per-slice dispatch approach used through slice 5, not the
slice plans themselves. **Governs** slices 6 through 13 (162 dispatched tasks), the Phase 0 work that
must land before slice 6 is dispatched, and the final audit after slice 13.

Slice 5 is included because it is not finished: it shipped with six recorded findings, none fixed, and
four of them have no work in the tree at all. Those four are Phase 0 items, not slice-13 items.

Everything numeric in this document was measured at the span or file named. Where a source heading and
its own table disagree, **both numbers are recorded and the disagreement is marked a finding**. No
count in this plan may be quoted forward without its locator.

## 1. What changed and why

Six changes. Each is a change to the *process*, each is justified by something that happened in slice 5,
and each has a cost recorded for getting it wrong.

### 1.1 Task briefs carry no test code

**What changed.** A brief states requirements, locators, traps, interfaces and a consequence grade. It
never contains an assertion, a matcher, an expected string, or a regex. Tests are written by the
implementer *after* the code exists, against the frozen source, not against the brief.

**Evidence.** Slice 5 shipped **ten brief-supplied assertions that were incapable of failing**. The
count was discovered incrementally and escalated six times as tasks ran: 2 → 8 → 9 → 10. The standing
ruling "the brief is a hypothesis, never an oracle" was made at position 2 of 26 and had to be restated
in every subsequent dispatch. Slice 13's own scope records the general form: *"the seventy-plus brief
defects last slice all came from assertions authored before the thing they asserted about."*

**Why it is not merely wasteful.** An implementer who changes working code to satisfy a broken brief
test has been taught wrong by the process. That is the failure mode: not a red suite, but a green one
over code that was correct before the brief arrived.

**Cost if wrong.** Implementers spend a little longer deriving their own assertions. That is the
intended cost.

### 1.2 The evidence audit runs first, before any dispatch

**What changed.** Phase 0 item 0.1 runs the citation audit on day one and puts the measured
strong/weak split into every dispatch verbatim. Every quotation in a brief is proved against the frozen
source before use — not only the matchers.

**Evidence.** Slice 5's citation defects were found on day four, not day one:

- `MOD-DOH-09` rendered the wrong one of the source's two precedence rules (`L14526` against `L14527`)
  under a heading that said *Safety controls*, and the screen additionally asserted that no safety-first
  ordering exists in the source. Eight modules had been built on that slice-4 ruling by the time it was
  checked.
- The JBS grant screen carried three refusal-reason strings claiming two locators name the Admin as
  drafter and Root SA as approver. Neither line names either role. A second false claim on the same
  screen cited **L44712**, a line containing the strings "JBS" and "grant" **zero times**.
- The gate's own doc comment recorded 6,511 / 408 / 1,153 / 4,950 citations. Measured today:
  **8,994 / 731 / 1,581 / 6,682**.

**Five of the ten C1 defects in slice 5 were citation defects.** The audit is a five-minute command.

**Cost if wrong.** Five minutes on day one, and a slightly noisier dispatch template.

### 1.3 Tasks are ordered by ruling-propagation risk, not by module number

**What changed.** Dispatch position is set by the fan-out of the open decisions a task will be forced to
settle. **The first consumer of a prose rule becomes its author.** Any decision with fan-out ≥ 2 is
stripped out of the module tasks entirely and given its own wave-0 representation task. Module number
is used only inside wave 2, where ordering is genuinely free.

**Evidence.** Slice 5's ledger carries 78 `Ruling` lines. The phrase "Cost if wrong" appears 30 times.
The phrase **"Cost if late" appears zero times**. Fan-out and cost turned out to be independent; fan-out
and *position* together determined cost:

| Ruling | Position | Fan-out | Cost |
|---|---|---|---|
| matrix type vs data ownership | 1/26 | 18 | ~0 — "one type moves between two files that both already exist" |
| brief-is-a-hypothesis | 2/26 | 24 | ~0 forward |
| `routedTo` adopted surface-wide | 11/26 | ~17 | **3.8 h**, 560 cells reclassified, definition settled twice, 17 declarations audited, 7 deleted as false claims, 8 left decorative, gate 17 added last |
| `registries/generated` ownership | 15/26 | many | shipped incomplete, re-hit independently by T16 and T17, forced a mid-slice generator-contract redesign, and the resulting gate was **still vacuous inside `pnpm verify`** when task 26 found it |
| another-surface row is never an enabled control (R22) | 18/26 | ~8 | a **live defect past typecheck, lint and a green suite**, on `MOD-STU-13` — a module the plan had listed by name as an R22 instance |
| locator fidelity | never scheduled | all | 6 unplanned tasks, 8,994 citations, a false claim about the source rendered on screen |

Every ruling made at position ≤ 5 cost approximately nothing. Every ruling made at position ≥ 11 cost a
retrofit, a re-settling, or an unplanned task, **irrespective of fan-out**.

`routedTo` was predictable before dispatch: the string `routedTo` appears **zero times** in all 2,381
lines of the slice-5 plan, while the plan states the ABSENT-versus-DISABLED rule twice in prose, flags
its own weakness in the same sentence ("The rule is derived, not quoted"), and instructs eighteen
authors to apply it "by rule … not cell by cell from intuition". An instruction warning eighteen authors
off intuition is an admission that intuition is what the plan supplies.

**Cost if wrong.** A false positive is one wave-0 task producing a field two modules use — under an hour,
and the field is still correct. A false negative is unbounded and grows with position. Bias hard toward
declaring wave-0 items.

### 1.4 Concurrency is unblocked before slice 6 starts, not managed around

**What changed.** Phase 0 closes the three remaining cross-process holes and hoists the probe convention.
After that: **path-disjoint editing agents are unbounded**; **whole-suite test runners are capped at one
until 0.4 lands, then uncapped**. The old cap of three is retired — it was sized for a defect that is now
fixed, and it is simultaneously too high for test runners and needlessly low for writers.

**Evidence, measured on this HEAD.** `pnpm test:unit` → 63 files / 2,062 tests, 5.4 s at 484 % CPU.
`pnpm test:component` → 46 files / 1,737 tests, 82.5 s at 410 % CPU. sha256 over all 17 files in
`registries/generated` before and after both suites: **identical**. `git status --porcelain` after:
**empty**. Both historical writers are genuinely fixed (`tests/unit/registry-build.test.ts:30-43` and
`tests/component/stu-shell.test.tsx:837-848` redirect through `AVIIXA_REGISTRY_OUT`, enforced by
`registry-freshness` gate 2 walking exec *call sites*).

What is **not** fixed, and is invisible inside a single `pnpm verify`:

- `tests/coverage/registry-freshness.test.ts:59-63` `walk()` is the one walker of `registries/generated`
  with no `isForeignProbe` exclusion, and it is the one comparing **file sets**. Two concurrent
  `pnpm test:release` processes give a false red. Masked only by `fileParallelism: false`, which is
  intra-process.
- `tests/unit/stu-training.test.ts:73-80` walks `src/studio` with no probe exclusion and feeds every file
  into a prohibited-phrase scan; `tests/component/stu-shell.test.tsx:812` plants into that directory.
  `tests/unit/stu-localisation.test.ts:78-85` does the same over all of `app/`.
- `.zz-probe-*` is in `.gitignore` **and** skipped by every gate's `isForeignProbe`, so an orphan is
  invisible to `git status` and to every gate at once. **There is one in the tree right now:**
  `app/super-admin/.zz-probe-92896/Probe.tsx`. It is inert only because it holds no `page.tsx`;
  `scripts/build-registries.mjs:293` `walkDirs` descends into dot-prefixed directories, so an orphan
  carrying a `page.tsx` and `MOD-*` tokens would mint a phantom route owner. That is F4's mechanism with
  no author.

### 1.5 Rigour is graded by consequence, not applied uniformly

**What changed.** Four grades. C1 gets a built-artefact gate, a mandatory independent pin, two plants,
and one end-to-end red inside `pnpm verify`. C2 gets a completeness gate and two plants. C3 gets
derive-and-assert-what-you-derived with one plant run twice. C4 gets no gate and no plant. On matrices,
plant **per column and per row-class, never per cell**.

**Evidence.** Slice 5's true plant count is **~480**, not 250 — fifteen tasks state an explicit "N planted
defects" summing to 360, and T2's 34-mutation proof, T3's 19 vocabulary plants, T5's 13, T24's 27,
gate 7's 7 and gate 17's 11 take it to ~480 across ~30 dispatches.

Of the **ten C1 defects**: five were found by independent cross-check against the frozen source, four by
an implementer reading the source against its brief, one by an independent render scan.
**Zero of ten by planting.** Planting's real yield was ~18 holes in suites and 5 gates that could not
fail — defects that had not happened yet, against ten that already had.

All four permission-shaped C1 defects ran along a **row-class or a column**, never along a cell:
row-vs-cell (T1), another-surface token read as a local control (T18, R22), revoked grant rendered
ABSENT (T6), any-column vs this-persona routing (`routedTo` consume), scope enforced on the read for one
branch and on the draw for the other (T17). Per-cell planting bought exhaustive coverage of a failure
mode that did not occur once in 184 cells.

**Cost if wrong, stated honestly.** The row-class × column budget does not cover a cell defect orthogonal
to both axes. That is the residual: one persona's permission rendering wrongly on one row of one matrix.
Slice 5 produced zero of those in 184 cells. The mitigation is 1.3 plus making `routedTo` consumed by
every declaration, which turns the per-cell question into a derivable fact.

### 1.6 Gates are planted inside the shipping pipeline, not only in isolation

**What changed.** Every C1 gate must be seen red **once, end to end, inside `pnpm verify`** — not only in
its own file.

**Evidence — F1, the meta-finding.** `verify` = `typecheck && lint && test:unit && test:component &&
build && test:release && test:e2e`, and `build` = `pnpm build:registries && next build`. Step 5 rewrites
`registries/generated/` in place; the freshness gate reads that same tree at step 6. **The gate cannot
fail where it actually runs.** Confirmed against `package.json:9,18` today; the file is unmodified since
2026-08-20 15:34.

Every gate on this build was planted in isolation. **Not one was ever planted inside the pipeline that
ships.** ~480 isolated plants could not detect this, because the property they test is not the property
that failed. A gate can be correct and vacuous where it runs.

The vacuity audit over `tests/coverage/` has been run (list and result in §2, item 0.2). Only
`static-export.test.ts`'s two existence checks share F1's property, and they are harmless smoke checks.

## 4. The brief template

A task brief is a **hypothesis with locators**. It is not an oracle, and it is not a test file.

### 4.1 What a brief contains

**1. Identity.** Slice, task number, wave, and the one-line statement of what exists when this task is done.

**2. Consequence grade — C1 / C2 / C3 / C4 — stated at the top**, because it decides the whole rigour budget
(§5). If a task spans grades, it carries the highest and names which artefact carries which.

**3. Requirements, prose, no code.** What must render, what must not, what must be disclosed. Every
requirement carries the locator it came from. A requirement with no locator is not a requirement; it is
someone's memory and must be marked as a build decision under APP-012.

**4. Locators, and only locators that were measured.** Line spans, row counts, and the span at which the
count was taken. Where a source heading and its own table disagree, **both numbers, marked a finding**.
Where something could not be established, the field-slot ships **marked unrecorded** — never inferred, never
filled with a plausible value.

**5. Traps, each with its grade, its locator, and the one sentence saying what an implementer builds wrongly
if they read only the token.** A trap without "why" is a warning nobody can act on.

**6. Interfaces this task consumes and interfaces it publishes.** Exact file paths. Anything it publishes
that another task consumes makes it a wave-0 task (§1.3) — if that is discovered while writing the brief,
**stop and re-order rather than shipping the brief**.

**7. Files this task owns, exactly.** No two tasks in a wave share a path. Directory moves are declared as a
MOVE owned by one task, never as N tasks editing one directory.

**8. What this task must NOT do.** The adjacent module, the other surface, the already-shipped route, the
decision it must disclose rather than settle.

### 4.2 What a brief never contains — and why

**NO TEST CODE. NO ASSERTIONS. NO MATCHERS. NO EXPECTED STRINGS. NO REGEXES.**

Slice 5 shipped **ten brief-supplied assertions that were incapable of failing**, discovered incrementally
and escalated six times (2 → 8 → 9 → 10). Slice 13's scope records the general form: the seventy-plus brief
defects in that slice all came from assertions authored **before the thing they asserted about**.

The reason is not tidiness. **An implementer who changes working code to satisfy a broken brief test has
been taught wrong by the process.** The failure mode is not a red suite — it is a green one over code that
was correct before the brief arrived. A brief that ships an assertion has pre-committed the implementer to a
claim nobody checked against the source, and the implementer's incentive is to make the claim true rather
than to check it.

**Corollary, equally binding:** a brief's **quotations** are proved against the frozen source before use,
not only its matchers. Five of slice 5's ten C1 defects were citation defects — including a screen citing
**L44712** for a claim about JBS grants on a line containing the strings "JBS" and "grant" zero times.

**The implementer writes the tests after the code exists, against the frozen source.** The brief tells them
where to look. It does not tell them what they will find.

### 4.3 The three lines every dispatch carries verbatim

1. The measured citation strong/weak split from Phase 0.1.
2. *"This brief is a hypothesis. Prove its quotations and its locators against the frozen source before you
   build from them. If a locator is wrong, report it — do not build around it."*
3. *"Brief-supplied assertions known to be incapable of failing, to date: **ten** (slice 5)."*

### 4.4 The ruling note format

Every ruling recorded during a task carries two lines, not one:

```
Cost if wrong:  <what breaks, and how big the repair is>
Cost if late:   <N tasks × the retrofit>   ← a non-zero value here means it should have been wave 0
```

The second line is new. Slice 5 has 78 rulings, 30 "Cost if wrong" lines, and **zero** "Cost if late" lines.

## 5. The rigour policy, per consequence grade

Derived from the measured slice-5 record: **~480 plants across ~30 dispatches produced zero of the ten C1
findings.** Five of ten were found by independent cross-check against the frozen source, four by an
implementer reading the source against its brief, one by an independent render scan. Planting's yield was
~18 holes in suites and 5 gates that could not fail — **defects that had not happened yet, against ten that
already had.**

### 5.1 C1 — a wrong claim about the source, or a permission rendering wrongly

- **Gate: mandatory**, and it reads `out/**`, **not the component tree.** The second aria-prohibited-attr
  site in slice 5 lived on a screen no composed journey reaches, and only the built-tree gate found it.
- **Independent pin: mandatory**, and **structural** wherever the authority can be read directly — as gate 7
  does by parsing the frozen source at run time, so there is no second copy to corrupt.
  (`slice-04-gates.test.ts:1913` is the pattern: parse the workflow order out of the source at run time.)
- **Two plants, and only two:**
  1. **Delete the subject.**
  2. **The consistent lie** — move the claim *and* its corroborating copy together. **This is the only plant
     shape on this build that ever defeated a check written in good faith.**
- **On matrices: plant per COLUMN and per ROW-CLASS, never per cell.** All four permission-shaped C1 defects
  in slice 5 ran along a row-class or a column; zero ran along a cell in 184 cells.
- **One end-to-end red inside `pnpm verify`** — the thing slice 5 never did for any gate (§1.6).

### 5.2 C2 — a declaration that is never consumed, or a cross-surface act built as a control

- **Gate: mandatory, and it is a COMPLETENESS gate** — enumerate declarations from the tree, assert the
  enumeration, then assert **every** declaration is consumed. `routedTo` (17 declared, 3 read) and task 20's
  `stage` field are the same defect, and **both are invisible to any gate that counts rather than
  enumerates**.
- **Two plants:** add a declaration and prove the enumeration notices; remove the consumption and prove the
  fold reds.
- **Per-declaration plants only on a mechanism's first landing.**
- **Pipeline proof only if the gate reads `out/**`.** Independent pin only for cross-surface acts, and then
  against **the target surface's own cell** ("actually permits" means *the target must permit THIS PERSONA*
  — settled in slice 5 against the source).

### 5.3 C3 — a derived number, a census, a generated artefact

- **Gate: mandatory, and it is derive-and-assert-what-you-derived — never a pinned literal.**
- **No independent pin: the derivation IS the independence** — provided the generator cannot write its own
  subject.
- **One plant per derived artefact, run TWICE IN A ROW.** The second run is the entire point: under the old
  assertion, a plant went green because the check repaired its own evidence
  (`registry-build.test.ts` generated over the registries it compared).
- **No plant in the pipeline, but a MANDATORY ORDERING AUDIT per release gate** (Phase 0.9): does any earlier
  step in `verify` rewrite this gate's subject? **One grep, not one slow proof. The report is the list
  checked.**

### 5.4 C4 — a comment, a doc citation, a cosmetic annotation

- **No gate and no plant.** Typecheck, lint, one assertion.
- Doc and comment citations get a **sweep once per slice**, not a maintained gate. Slice 5 spent real design
  effort defending the doc-citations exemption (documents legitimately quote a wrong citation in order to
  correct it) for a class whose worst outcome is a confused reader.
- **ONE exception, and it is the only place planting is irreplaceable:** a field that duplicates another
  module's authority gets one plant. Task 20's `stage` field and the `routedTo` decoration are C4 today and
  **C2 the moment the other module's row moves**, and planting is the only thing that has ever found one.

### 5.5 Budget and the honest residual

**~480 plants → ~140. Roughly seven in ten skipped.** The saving is almost entirely the collapse of per-cell
and per-pair enumeration: T6's 35 plants over 184 cells become **12** (8 columns + 4 row-classes); T7's 27
over 42 pairs and T12's 44 over 16 pairs become **3-4 each**; T3's 19 vocabulary plants become **3 plus one
completeness plant**. **The C1 gate budget goes UP**: every C1 gate gains a consistent-lie plant and an
end-to-end pipeline proof it has never had.

**What is lost:** 10-15 per-cell test-coverage holes on C1 matrices (T6's six green-first-time plants, T11's
three, T22's two, T18's one). **Those are holes in tests, not defects in code.**

**The residual, stated without dressing:** a per-cell hole on a C1 permission matrix would render one
persona's permission wrongly on one row. Neither the row-class plant nor the completeness plant is per-cell.
The mitigation is the row-class × column budget, which covers the axis all four real permission defects ran
along; the exposure is a cell defect orthogonal to both axes, and **slice 5 produced zero of those in 184
cells.** Per-cell planting cannot close it either — a per-cell plant only exists where a test already exists,
so it proves the cells you tested are tested and can never prove you tested every cell. **The completeness
plant defends the failure mode that actually matters: a cell or a module added and never covered.**

**Insurance, bought with part of the ~340 saved plants:** make `routedTo` consumed by all seventeen
declarations rather than three. A cell whose ABSENT-versus-DISABLED rendering is **derived from the target
surface's own cell** cannot be wrong in isolation. That converts the residual per-cell risk into a derivable
fact, which is what `routedTo` was adopted for.

### 5.6 The binding-decidable test (run once per slice, before the first dispatch, ~30 min)

Inputs: that slice's §1 Global Constraints, its per-module contract, and the previous slice's ledger. For
each rule bullet:

1. **Does it name a symbol that already exists in the tree?** (`evaluateStudioAccess`, `StudioShell`,
   `src/domain/clock.ts`, the `Exclude<...> extends never` pattern.) If yes — the rule is already carried by
   a mechanism. **Risk zero, no action.** This is exactly why "affordances are driven per-control through
   `evaluateStudioAccess`" cost nothing all slice: **the rule named the function.**
2. **If no: does applying it require a per-instance classification of a cell, a row, a state or a branch?**
   If yes, its fan-out is the number of tasks holding an instance of that kind, countable from the plan's own
   matrix table.
3. **Has it been re-litigated before?** Grep the previous ledger for the subject. An adjudication, a
   contested fixture, a "carried", a deferred lift, or "two modules rendering the same shape differently"
   means **the prose is known not to bind**.

**A bullet answering no / yes / (either) is a BINDING DECIDABLE. Fan-out ≥ 2 makes it a wave-0 task.**

**The 60-second version**, when there is no time for the full pass: grep the plan for the tells a document
uses when it knows a rule will not bind and hopes anyway — *"by rule"*, *"not from intuition"*, *"derived,
not quoted"*, *"every module must"*, *"are NOT re-litigated"*, and any *"X → ABSENT; Y → DISABLED"*-shaped
outcome pair **with no field named between them**. Slice 5's plan has four hits and two of them are the two
rulings that cost the slice. Cross-hit against the prior ledger; **two hits on one subject is a wave-0 item.**

**What a wave-0 task ships, and nothing else:** the field or type; the **predicate** that derives it, so the
classification is data rather than an author's judgement; an exhaustiveness or completeness check; one gate
with a planted red; **applied to exactly TWO instances chosen to be maximally different** — not to all, and
never to one. Two dissimilar instances is the cheapest thing that would have exposed "actually permits"'s two
readings at definition time instead of after seventeen modules had declared it. **No screens, no routes.**
